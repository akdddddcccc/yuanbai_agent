## 3. 当前页面与交互

### 首页 `/yuanbai/`

- 保留原站的 3D 元白楼、灯光、底部投影、侧边刻度、悬浮卡片视觉。
- 主要入口为“探索元白”，已移除 Agent / 对话入口。
- 规则不再占一张独立大卡片，而是在首次进入游戏后自动弹出。
- 页脚保留“探索规则 · 重看互动教学”。

### 初次感知 `/yuanbai/tutorial/`

- 自动弹出规则介绍，可选择开始互动教学或直接进入游戏。
- 4×4 固定教学地图，复用正式游戏的 Canvas 渲染、地板材质、角色、工具、声音与动画。
- 教学操作顺序：`W → 1 → W → E → 2 → W → 3`。
- 每一步显示文字解说；当前按键或道具带呼吸光晕、扩散光圈和就近提示，其他操作弱化。
- 动画播放完再进入下一步。探测只标出安全落点，不移动玩家。
- 支持鼠标、触屏、键盘；系统要求减弱动态效果时使用静态高亮。
- 教学不创建计分局、不提交成绩。完成后转入正式游戏。

### 正式游戏 `/yuanbai/explore/`

- 仍为 9×9 地图、66 个安全格，正式核心规则和服务端动作重放保持一致。
- “学院首页”返回学校专属入口；“探索规则”内提供重看互动教学。
- 排行榜调用同来源 `/api/yuanbai/game/`，等待学校现场接通后端。

### 首次访问的准确行为

浏览器使用 `yuanbai-school-onboarding-v2` 记录教学状态：进入教学即写入 `seen`，完成或跳过写入 `complete`。正式游戏检查是否存在这个键；存在就不再自动进入教学。因此中途离开后也不会反复强制引导。

该状态属于当前网站来源和当前浏览器，不跨域、不同步到账号。清除站点数据、更换浏览器或更换域名后会重新触发。主动访问教学地址始终可以重看。浏览器禁止本地存储时，正式游戏不会因存储异常而卡住，但无法可靠保存教学状态。

## 5. 关键实现说明与注释约定

### 5.1 不要直接改构建产物

`dist-school/` 是生成目录，每次构建会重新生成。修改其中的 HTML、JS、CSS 会在下次构建时丢失。正确做法是修改上表列出的源码，再执行学校构建。

### 5.2 教学控制器不是独立 JS 模块

`school/tutorial/lesson.js` 在构建时被插入正式 `game.js` 的闭包中，因此可以使用原游戏的 `game`、`ui`、`canvas`、`busy()`、`resize()`、`toast()` 等对象。不要直接给 HTML 增加一个独立 `<script src="lesson.js">`，否则这些变量不存在。

教学复用以源字符串替换实现。`once()` / `replaceOnce()` 找不到唯一锚点时会报错；同步新版正式游戏源码后，要检查构建脚本锚点并重新验收教学。不要为“让构建过关”而盲目删掉唯一性检查。

### 5.3 光晕调整位置

- 强度：`immersive.css` 中 `#lesson-focus` 与 `@keyframes lesson-breathe` 的阴影、边框颜色。
- 呼吸速度：`lesson-breathe` 当前周期 `2.2s`，扩散圈 `lesson-ripple` 同步为 `2.2s`。
- 扩散范围：`lesson-ripple` 的缩放、`:after` 的 `inset`。
- 非当前按钮明度：`.lesson-has-target` 下的 `opacity`。
- 上方按键标签：`#lesson-next-key`；按钮旁提示：`#lesson-focus > span`。
- 光圈使用 `pointer-events: none`，不能挡住实际按钮。定位需使用 `getBoundingClientRect()`，因为键盘带等距变换。
- 保留 `prefers-reduced-motion` 的静态高亮方案。

### 5.4 地图与成绩隔离

教学固定起点为第 4 行第 1 列，左列从下向上依次拾取同伴、探测、全景。变更地图尺寸时必须同时检查起点、索引、拾取数量、渲染坐标、引导文案及动作门控。

正式服务端重放仍使用原始 `public/explore/core.js`；不要把生成的 4×4 教学核心替换到正式游戏或后端。学校玩家浏览器键使用 `yuanbai-school-*` 命名，不复用原站的前端身份键。

## 6. 接手后本地运行

安装 Node.js 24 或以上，在源码根目录执行：

```powershell
npm ci
npm run school:dev
```

打开 `http://127.0.0.1:4321/yuanbai/`。该地址仅代表运行预览的这台电脑，不是学校公网地址。预览已运行时直接复用，不要再启动第二个实例占用 4321。

只刷新构建文件：

```powershell
npm run school:build
```

然后刷新浏览器。学校预览不是自动热更新；新增源文件或改内容后需要重建。不要用根目录的 `npm run dev` 代替学校预览；那是原站开发入口，接口行为不同。

验证：

```powershell
npm run school:test
```

若需要重新验证“首次进入”，最简单是在隐私窗口打开首页；只重看教学则使用首页页脚或游戏内“探索规则”。

## 7. 部署边界与步骤

详细现场操作见 `school/README.md`，部署包根目录也附 `部署说明.md`。

1. 用户确认排版和交互后，再将部署包解压到新的学校目录，例如 `D:\yuanbai-school`。
2. Nginx 只映射该目录下的 `public/`；数据、备份、源码、运行时不能通过网页目录公开。
3. 使用 `college-config.example.json` 生成现场配置，核实真实公开 HTTPS 来源。模板中的域名是待核实值，不代表本次已验证公网 HTTPS。
4. 导入原榜单快照后，以 `readOnly: true` 启动校验；配置默认不接受新成绩。
5. 参考 `deploy/nginx-school.conf` 替换相关游戏路径与 API 代理。只改对应片段，保留 8080、8083 原服务及其路由；避免新旧路径同时命中。
6. 校验 Nginx 配置成功后再 reload。核对页面与同来源 API 都经过学校对外网关。
7. 成绩核对和公网验证完成后，将排行榜设为可写，并用学校服务管理方式托管，确保重启后恢复。

仅更新网页文件不需要重启 Nginx；修改 Nginx 配置才需校验并 reload。排行榜后端代码或配置变化则重启该独立服务。后续从学校分支构建并更新 `public/`，不要覆盖数据目录和现场配置。

旧学校站已能通过 oa 域名公网访问是用户此前确认的信息；本交接没有重新检测其当前公网状态，也没有更改官方站点的域名或网关配置。若切换到学院官网子路径，需要管理员接通网页和 API 路由，不能只改前端链接。

## 8. 原排行榜成绩迁入学校榜单

目标是把现有双榜与相关记录作为快照迁入，之后两站独立记录新成绩，不进行实时同步。

1. 在原排行榜服务器以 Node 24+ 运行 `database-transfer.mjs export`，生成一致性 SQLite 快照及同名 `.manifest.json`。不要直接复制正在写入的主库文件，以免遗漏 WAL 中的已提交数据。
2. 通过已授权渠道将两份文件一起传到学校非公开备份目录。
3. 用 `restore` 恢复到尚不存在的新数据库文件；工具核验哈希、完整性、表记录数与迁移版本。
4. 只读启动，核对正常榜、坠落榜、昵称、人数与成绩。
5. 正式开放后两站各自新增成绩。再次迁移不能覆盖已有学校新成绩；需要另行设计合并方案。

数据库会保留玩家身份关联和昵称归属，但浏览器令牌不会自动跨域搬迁。因此老玩家不会仅因迁库而在学校域名自动登录，已有昵称也不会被重新分配。若要求老玩家继续使用原身份，需要另做身份转移设计，当前未实现。

## 10. 回退与交接原则

上线前备份现有网页和 Nginx 配置，放在非公开目录。网页异常时恢复上一版网页；配置异常时恢复经过验证的配置。数据库开始接受新成绩后，不能为了回退网页而恢复旧数据库快照。

维护人员优先改 `school/` 和学校构建脚本，保留共享游戏规则与服务端校验的一致性。交接包和文档均不包含账号密码、访问令牌或真实成绩库；远程登录由持有授权的人员完成。
